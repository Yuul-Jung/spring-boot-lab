04실습 A — 설치 상태·서비스 점검

1. 기존 설치 확인

CODE · bash
# 이미 설치되어 있다면 재설치하지 않는다
command -v ollama
ollama --version
systemctl is-active ollama
ollama list
# GPU 메모리 사용량 확인(엔비디아 GPU가 있을 때)
nvidia-smi
예상 출력 (실제 실행 미검증) ollama version ... / active / NAME ID SIZE MODIFIED
코드 풀이 — 이 코드가 무엇을 하는가

설치 여부와 서비스 상태를 분리해서 확인한다. 서비스가 inactive이면 설치가 되어 있어도 API 호출이 실패한다.

2. 공식 설치 절차

CODE · bash
# 공식 설치 스크립트를 로컬에 내려받는다
curl -fsSL https://ollama.com/install.sh -o /tmp/ollama-install.sh
# 내용을 확인한 후 실행한다
less /tmp/ollama-install.sh
sh /tmp/ollama-install.sh
# systemd 서비스 시작 및 자동 시작 설정
sudo systemctl enable --now ollama
ollama --version
예상 출력 (실제 실행 미검증) ollama version ...
코드 풀이 — 이 코드가 무엇을 하는가

원격 스크립트는 실행 전 내용을 확인한다. 기존 설치가 정상이라면 이 과정을 건너뛴다.

3. 서비스 및 API 연결 확인

CODE · bash
# 서비스가 실행 중인지 확인
systemctl status ollama --no-pager
# 기본 로컬 포트(11434)의 모델 목록 API 조회
curl -fsS http://127.0.0.1:11434/api/tags
예상 출력 (실제 실행 미검증) {"models":[...]}
코드 풀이 — 이 코드가 무엇을 하는가

localhost 기본 접속만 사용한다. 외부 공개용으로 0.0.0.0 바인딩하지 않는다.

05실습 B — 대화 모델 다운로드·실행

4. 모델 다운로드

CODE · bash
# 실습용 소형 대화 모델
ollama pull qwen2.5:3b
# 다국어 임베딩 모델
ollama pull bge-m3
# 내려받은 모델 확인
ollama list
예상 출력 (실제 실행 미검증) qwen2.5:3b ... / bge-m3 ...
코드 풀이 — 이 코드가 무엇을 하는가

대화 모델은 문장 생성, 임베딩 모델은 문장을 수치 벡터로 바꾸는 용도다. 디스크 공간과 GPU/RAM 여유를 확인한다.

5. 터미널에서 대화 모델 실행

CODE · bash
# 대화형 인터페이스 실행
ollama run qwen2.5:3b
# 프롬프트: 벡터 데이터베이스를 한 문장으로 설명해줘
# 종료: /bye
예상 출력 (실제 실행 미검증) 벡터 데이터베이스는 ...
코드 풀이 — 이 코드가 무엇을 하는가

자연어 질문에 대한 텍스트가 반환되는지 확인한다. 답변 문구는 매번 달라질 수 있다.

06실습 C — 대화 API

6. 대화 API 호출

CODE · bash
curl -fsS http://127.0.0.1:11434/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen2.5:3b","stream":false,"messages":[{"role":"user","content":"RAG를 한 문장으로 설명해줘."}]}'
예상 출력 (실제 실행 미검증) {"model":"qwen2.5:3b","message":{"role":"assistant","content":"..."}, "done":true, ...}
코드 풀이 — 이 코드가 무엇을 하는가

stream:false로 응답을 하나의 JSON 객체로 받아 구조를 확인한다. message.content가 생성된 답변이다.

07실습 D — 임베딩 API

7. 임베딩 API 호출

CODE · bash
curl -fsS http://127.0.0.1:11434/api/embed \
  -H 'Content-Type: application/json' \
  -d '{"model":"bge-m3","input":["전압과 전류의 관계","오늘의 날씨"]}'
예상 출력 (실제 실행 미검증) {"model":"bge-m3","embeddings":[[0.01,...],[0.02,...]], ...}
코드 풀이 — 이 코드가 무엇을 하는가

embeddings 배열에는 입력 문장 수와 같은 개수의 벡터가 들어간다. 숫자 값과 벡터 길이는 모델과 실행 환경에 따라 달라진다.

8. 벡터 개수와 차원 검사

CODE · bash
# jq가 없다면 설치한다
sudo apt install -y jq
# 두 문장을 보내고 결과의 벡터 개수·차원만 확인
curl -fsS http://127.0.0.1:11434/api/embed \
  -H 'Content-Type: application/json' \
  -d '{"model":"bge-m3","input":["모터 제어","모터 드라이버"]}' \
  | jq '{count:(.embeddings|length),dimensions:(.embeddings[0]|length)}'
예상 출력 (실제 실행 미검증) {"count":2,"dimensions":1024}
코드 풀이 — 이 코드가 무엇을 하는가

BGE-M3 기본 임베딩 차원은 1024이다. 출력값이 일치하는지 실제 API로 검증한다.

08실습 E — 자원 정리

9. 실습 종료 후 모델 메모리 해제

CODE · bash

ollama ps
# 사용하지 않는 대화 모델 언로드

# 임베딩 모델도 필요 없으면 언로드

예상 출력 (실제 실행 미검증) NAME ... (ollama ps에서 실행 중인 모델 확인)
코드 풀이 — 이 코드가 무엇을 하는가

모델을 stop해도 다운로드 파일은 남는다. 다음 실습에서 재사용할 수 있다.

13핵심 정리

Ollama 서버는 모델을 실행하는 로컬 서비스다. 대화 모델은 문장을 생성하고 임베딩 모델은 문장을 벡터로 변환한다. 두 API의 입력·출력을 분리해 검증해야 RAG 파이프라인의 오류를 빠르게 찾을 수 있다.
