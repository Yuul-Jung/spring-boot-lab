00개요·입출력 정의

제07장의 Elasticsearch(엘라스틱서치, 검색 엔진) 키워드 검색을 확장하여 벡터 검색과 Hybrid Search(하이브리드 서치, 혼합 검색)를 비교합니다. 검색 입력은 질문 문자열, 출력은 문서 ID·점수·제목입니다.

입력검색어, 3차원 실습용 벡터, 문서 4개
출력BM25(비엠25, 키워드 관련도)·kNN(케이엔엔, 최근접 이웃)·RRF(알알에프, 순위 융합) 결과
완료 기준세 방식의 검색 결과를 비교하고 순위가 다른 이유를 설명한다.

08Python RRF 통합 실습

두 검색의 JSON 결과에서 _id를 추출하여 RRF = Σ 1/(k + rank)를 계산합니다. 같은 문서가 두 결과에서 높은 순위를 차지하면 융합 점수가 증가합니다.

PYTHON · 실행 코드 
# 파일명: lab08_rrf.py — Python 표준 라이브러리만 사용
import json
from urllib.request import Request, urlopen

BASE = "http://localhost:9200/lab08_docs/_search"


def search(payload):
    data = json.dumps(payload).encode("utf-8")
    req = Request(BASE, data=data,
                  headers={"Content-Type": "application/json"},
                  method="POST")
    with urlopen(req, timeout=10) as response:
        return json.load(response)["hits"]["hits"]


keyword = search({
    "size": 4,
    "query": {"multi_match": {
        "query": "센서 직렬 통신", "fields": ["title", "body"]
    }}
})
vector = search({
    "size": 4,
    "knn": {"field": "embedding",
            "query_vector": [1.0, 0.0, 0.0],
            "k": 4, "num_candidates": 4}
})

# 두 검색의 순위를 합산한다. 1위는 1/(60+1)을 더한다.
scores = {}
titles = {}
for hits in (keyword, vector):
    for rank, hit in enumerate(hits, start=1):
        doc_id = hit["_id"]
        scores[doc_id] = scores.get(doc_id, 0.0) + 1 / (60 + rank)
        titles[doc_id] = hit["_source"]["title"]

print("BM25:", [hit["_id"] for hit in keyword])
print("kNN :", [hit["_id"] for hit in vector])
print("RRF 결합 결과:")
for doc_id in sorted(scores, key=lambda d: (-scores[d], d)):
    print(doc_id, titles[doc_id], f"{scores[doc_id]:.6f}")
BASH · 실행 코드 
# Python 코드 실행
python3 lab08_rrf.py
예상 출력 형식 — 실제 순위는 실행환경에 따라 변동
BM25: ['...', '...']
kNN : ['1', '2', ...]
RRF 결합 결과:
문서ID 문서제목 융합점수

서버에서 실제 검색한 결과를 입력으로 사용합니다. 점수는 각 검색의 원시 점수를 더한 것이 아니라 순위의 역수를 합산한 값입니다. 이 구현은 학습용이며 동점 처리·필터·대량 데이터 운영 기능은 별도 확장이 필요합니다.

09검색 비교·해석

방식기준강점주의
BM25토큰·빈도정확한 용어 검색표현이 다르면 누락 가능
kNN벡터 거리유사 의미 탐색임베딩 품질 의존
RRF순위 융합서로 다른 검색 결과 결합가중치·k·후보 수 조정 필요

이번 장의 3차원 좌표는 임베딩 품질을 평가하기 위한 데이터가 아닙니다. 제09장부터 실제 문서 청크와 Ollama 임베딩을 적용합니다.

10검증·오류 점검

검증정상 조건
서버HTTP 200 및 버전 확인
매핑embedding 필드 dims=3
색인_bulk errors=false, count=4
검색BM25·kNN 각각 hits 배열 반환
통합RRF 문서 ID별 순위 출력

오류별 조치: connection refused → Docker 서비스/포트 확인. dimension mismatch → 벡터 차원 확인. HTTP 401 → 이전 장과 보안 설정 불일치 확인. Python KeyError → Elasticsearch 오류 JSON과 hits 구조 확인. 실제 실행 결과는 아직 수집되지 않았습니다.
