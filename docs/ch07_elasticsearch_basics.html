01과제 개요 · 입력과 출력

제06장의 PostgreSQL/pgvector는 벡터 영속 저장에 집중했습니다. 이번 장은 Elasticsearch(엘라스틱서치, 검색 엔진)를 Docker로 실행하고 문서 색인·키워드 검색을 수행합니다. 제08장의 벡터 검색과 혼동하지 않습니다.

입력Ubuntu 24.04, Docker Engine/Compose, 실습용 JSON 문서 3개
출력실행 중인 Elasticsearch, lab_articles 인덱스, 검색 결과
완료 기준상태 확인 → 인덱스 생성 → 문서 적재 → match 검색 → 정리

Index(인덱스, 검색 대상 논리 집합)는 문서가 들어가는 공간이고, Mapping(매핑, 필드 자료형 정의)은 검색 방법에 영향을 줍니다. text는 분석되는 본문, keyword는 정확한 값 비교에 사용합니다.

05실습 폴더와 Compose 파일

실습 폴더는 홈 디렉터리 아래 새로 만들며 기존 프로젝트를 변경하지 않습니다. 이 장에서는 로컬 전용 단일 노드·보안 비활성화 설정을 사용합니다. 외부 서버나 공개망에 배포하면 안 됩니다.

터미널 · 실습 폴더 만들기 
mkdir -p ~/spring-ai-lab/ch07
cd ~/spring-ai-lab/ch07
nano compose.yaml
compose.yaml · 전체 내용 
services:
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.17.8
    container_name: spring-rag-es07
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - ES_JAVA_OPTS=-Xms512m -Xmx512m
    ports:
      - "127.0.0.1:9200:9200"
    volumes:
      - es07data:/usr/share/elasticsearch/data
    mem_limit: 2g
volumes:
  es07data:
코드 풀이 — 설정 의도

discovery.type=single-node는 단일 노드 모드, ES_JAVA_OPTS는 JVM 힙을 512MB로 제한합니다. 127.0.0.1 바인딩은 로컬 접속으로 제한합니다. 교육용 버전은 예시로 고정했으며 실제 배포 전 이미지 태그의 존재·보안 공지를 확인해야 합니다.

07인덱스와 매핑 생성

터미널 · 인덱스 생성 
curl -sS -X PUT 'http://127.0.0.1:9200/lab_articles' \
  -H 'Content-Type: application/json' \
  -d '{
    "mappings": {
      "properties": {
        "title": {"type": "text"},
        "category": {"type": "keyword"},
        "body": {"type": "text"}
      }
    }
  }'
예상 출력
{"acknowledged":true,"shards_acknowledged":true,"index":"lab_articles"}
코드 풀이 — 왜 필드마다 다른 자료형인가

title과 body는 문장 검색용 text, category는 정확한 범주 필터용 keyword입니다. 한국어 형태소 검색은 별도 분석기 구성이 필요하며 이번 장의 기본 분석기는 한국어 의미 분석을 보장하지 않습니다.

08문서 3개 색인

터미널 · 문서 등록 
curl -sS -X PUT 'http://127.0.0.1:9200/lab_articles/_doc/1?refresh=true' \
  -H 'Content-Type: application/json' \
  -d '{"title":"Spring AI introduction","category":"java","body":"Spring AI connects Java applications to language models."}'

curl -sS -X PUT 'http://127.0.0.1:9200/lab_articles/_doc/2?refresh=true' \
  -H 'Content-Type: application/json' \
  -d '{"title":"Elasticsearch search","category":"search","body":"Elasticsearch indexes documents for full text search."}'

curl -sS -X PUT 'http://127.0.0.1:9200/lab_articles/_doc/3?refresh=true' \
  -H 'Content-Type: application/json' \
  -d '{"title":"Vector database","category":"search","body":"Vector search compares embeddings using similarity."}'

curl -sS 'http://127.0.0.1:9200/lab_articles/_count?pretty'
예상 출력 · 마지막 명령
{"count":3,"_shards":{"total":1,"successful":1,"skipped":0,"failed":0}}
코드 풀이 — 문서 저장

_doc/1은 문서 ID를 지정하고 refresh=true는 다음 검색에서 곧바로 조회할 수 있도록 갱신을 요청합니다. 실제 대량 적재에서는 매 문서마다 refresh를 호출하지 않습니다.

09match와 term 검색 비교

터미널 · 본문 키워드 검색 
curl -sS -X GET 'http://127.0.0.1:9200/lab_articles/_search?pretty' \
  -H 'Content-Type: application/json' \
  -d '{"query":{"match":{"body":"language models"}}}'
예상 출력 · 핵심 필드만 발췌
"hits": {
  "total": {"value": 1, "relation": "eq"},
  "hits": [{"_id": "1", "_source": {"category": "java", ...}}]
}
터미널 · 정확한 범주 검색 
curl -sS -X GET 'http://127.0.0.1:9200/lab_articles/_search?pretty' \
  -H 'Content-Type: application/json' \
  -d '{"query":{"term":{"category":"search"}}}'
예상 출력 · 핵심 값
"total": {"value": 2, "relation": "eq"}
"_id": "2"
"_id": "3"
코드 풀이 — 차이점

match는 분석된 텍스트에 적합하고 term은 분석하지 않은 정확한 값에 적합합니다. _score는 관련도 점수이며 확률이나 정답 보증값이 아닙니다.

오류 점검: 연결 거부 → 컨테이너 상태·포트 확인. JVM 종료 → 메모리 확인. 400 오류 → JSON·요청 경로 확인. 인덱스 중복 생성 → 400 resource_already_exists_exception이 발생할 수 있으며 기존 인덱스를 무단 삭제하지 않습니다.
