01과제 개요

제09장의 문서 적재와 제10장의 질문·답변을 PDF로 확장한다. 이번 장은 PDF → 페이지별 추출 → 청크 → 출처 메타데이터 → Elasticsearch 색인을 완성한다. 질문·답변은 기존 제10장 API를 재사용한다.

입력텍스트 선택 가능한 PDF 1개 (data/manual.pdf)
출력Elasticsearch rag_documents 색인, 페이지별 출처 정보
기존제09장 색인, 제10장 RAG API
추가PDF 페이지 추출, 페이지 번호, 파일 해시, 중복 색인 방지

스캔 이미지 PDF는 텍스트가 추출되지 않을 수 있다. OCR(광학 문자 인식)은 별도 확장 실습이다.

02전체 동작 구조

문서 적재
PDF 파일 → pypdf 페이지 추출 → 청크·페이지·해시 → Ollama bge-m3 → Elasticsearch rag_documents
질의 응답
질문 → 제10장 Spring AI API → Elasticsearch 검색 → Ollama 답변 → 출처 확인

원본 파일과 색인 문서는 별도로 관리한다. source와 page를 응답 출처에 표시하려면 제10장 응답 구성도 해당 메타데이터를 읽도록 확인해야 한다.

06PDF 적재 전체 코드

제09장의 인덱스 rag_documents에 동일한 필드명 content, embedding을 사용한다. 인덱스 매핑에서 embedding이 1024차원 dense_vector인지 먼저 확인한다. 다른 매핑이면 기존 인덱스를 수정하지 말고 별도 인덱스를 만든다.

ingest_pdf.py 
import hashlib
import os
from pathlib import Path

import requests
from pypdf import PdfReader

ES = os.getenv("ES_URL", "http://localhost:9200")
OLLAMA = os.getenv("OLLAMA_URL", "http://localhost:11434")
INDEX = "rag_documents"
PDF = Path("data/manual.pdf")
session = requests.Session()
session.trust_env = False  # 로컬 실습 요청에 프록시 적용 방지

def chunk_text(text, size=700, overlap=100):
    # 앞 청크의 마지막 100자를 다음 청크에 중복 포함
    step = size - overlap
    return [text[i:i + size] for i in range(0, len(text), step)
            if text[i:i + size].strip()]

def embed(text):
    response = session.post(
        f"{OLLAMA}/api/embed",
        json={"model": "bge-m3", "input": text},
        timeout=120,
    )
    response.raise_for_status()
    vector = response.json()["embeddings"][0]
    if len(vector) != 1024:
        raise ValueError(f"expected 1024 dimensions: {len(vector)}")
    return vector

def main():
    if not PDF.is_file():
        raise FileNotFoundError(PDF)
    digest = hashlib.sha256(PDF.read_bytes()).hexdigest()
    mapping = session.get(f"{ES}/{INDEX}/_mapping", timeout=20)
    mapping.raise_for_status()
    field = mapping.json()[INDEX]["mappings"]["properties"]["embedding"]
    if field.get("dims") != 1024:
        raise ValueError("embedding mapping must have dims=1024")
    total = 0
    for page_num, page in enumerate(PdfReader(str(PDF)).pages, 1):
        text = (page.extract_text() or "").strip()
        if not text:
            print(f"skip empty page: {page_num}")
            continue
        for chunk_num, content in enumerate(chunk_text(text), 1):
            doc_id = f"{digest[:16]}-p{page_num}-c{chunk_num}"
            doc = {
                "content": content,
                "embedding": embed(content),
                "source": PDF.name,
                "page": page_num,
                "chunk_id": chunk_num,
                "content_hash": digest,
            }
            result = session.put(
                f"{ES}/{INDEX}/_doc/{doc_id}",
                json=doc, timeout=120,
            )
            result.raise_for_status()
            total += 1
    session.post(f"{ES}/{INDEX}/_refresh", timeout=20).raise_for_status()
    print(f"indexed: {total}")

if __name__ == "__main__":
    main()
실행 
python ingest_pdf.py
예상 출력 (PDF에 따라 다름)

코드 풀이 — 이 코드가 무엇을 하는가

파일 SHA-256과 페이지·청크 번호로 고정 문서 ID를 만든다. 동일 PDF를 다시 실행하면 같은 ID가 갱신되므로 중복 증가를 방지한다. PDF 내용이 바뀌면 새 ID가 생성되므로 이전 버전 삭제는 별도 관리해야 한다. timeout과 HTTP 오류 검사를 포함한다.

08Spring AI RAG 연동

제10장의 검색 API에 PDF 내용에 대한 질문을 전송한다. 검색 결과에서 source, page가 반환되는지 확인한다. 기존 API가 출처를 파일명만 반환한다면 서비스의 출처 매핑에 페이지 필드를 추가해야 한다.

  "answer": "검색된 PDF 내용에 근거한 설명...",
  "sources": ["manual.pdf, p.1"]

질문으로 검색한 근거가 PDF 청크인지 확인한다. 출처의 페이지 번호가 누락되면 제10장의 응답 생성 코드를 보완해야 한다. 예시 응답은 실제 실행 결과가 아니다.

09검증 및 오류 점검

점검판정 기준
PDF 추출페이지별 문자 수가 0보다 큼
임베딩각 청크 벡터 길이 1024
인덱스rag_documents에 매핑 호환
출처파일명·페이지·청크 번호 저장
재실행동일 PDF에서 문서 ID 중복 생성 없음
응답제10장 검색·생성 API가 PDF를 근거로 사용

실패 사례: 404는 인덱스 없음, connection refused는 서비스 미실행, dims 오류는 임베딩 모델·매핑 불일치, 빈 페이지는 스캔 PDF 가능성을 의미한다.

10핵심 정리 및 다음 장

PDF 문서는 페이지별로 추출한 뒤 청크와 출처 메타데이터를 함께 저장해야 답변의 근거를 추적할 수 있다. 문서 내용의 정합성과 검색 품질은 별도 검증 대상이다.
